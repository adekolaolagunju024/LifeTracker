# Waypoint

A general-purpose personal goal tracker — Career is just one of the built-in project types; use it for any goal, in any area of life. Multi-user and collaborative, self-hosted, no external dependencies required to run locally.

Say a goal and get a phased plan; then **Start my day** sorts today's tasks and runs focus sessions with your music, **Your why** brings back what keeps you going when you'd give up, people who believe in you can **pledge a reward** for finishing, and every task moves your character along the **Journey**. Live at [waypointapp.com](https://waypointapp.com).

## Features

- **Accounts** — email/password registration and login, sessions scoped per user (`express-session`), an optional "Sign in with Google" (finds-or-creates an account by email), a "Keep me signed in" toggle (persistent 30-day session vs. a session-only cookie cleared when the browser closes), browser-native password-save support (real `<form>` submits + the Credential Management API), a "Forgot password?" flow that emails a one-hour reset link through Resend (where email isn't set up, the link is written to the server log instead), and self-service permanent account deletion from Settings (password-confirmed; every project/task row cascades with it). Passwords need at least 8 characters
- **Content Security Policy** on every response: everything loads from the site itself except Google Fonts and the music services' embedded players. No plugins, no framing by other sites, and forms post only to the site. Inline scripts are still allowed, because the markup uses inline event handlers; moving those into the script files is the step before `'unsafe-inline'` can go.
- **Security** — a fresh session id is issued at every sign-in (no session fixation); sign-in, sign-up and password-reset requests are rate limited (`backend/middleware/rateLimit.js`: 10 sign-in attempts per account per 15 minutes, 5 reset emails per hour), answering 429 with `Retry-After`; every response carries `X-Content-Type-Options: nosniff`, `X-Frame-Options: SAMEORIGIN`, `Referrer-Policy: strict-origin-when-cross-origin` and, in production, HSTS, with no `X-Powered-By` and no CORS headers (the app and API share one origin)
- **Two-step sign-in** — Settings → Account & Security → Two-step sign-in (`backend/twofactor.js`).
  - **Setup:** scan a QR code (or type the key) into any authenticator app, confirm a code, and save 10 single-use recovery codes. They're stored only as hashes and shown once; new ones can be made with a code.
  - **Signing in:** with it on, a correct password (or Google) holds the sign-in for 5 minutes until a six-digit code or a recovery code is given.
  - **Codes:** standard RFC 6238 TOTP (SHA-1, 30 s, ±1 step for clock drift), and a used code step can't be replayed. Code checks are rate limited.
  - **Turning it off** needs the password and a code.
  - **API:** `POST /api/auth/2fa/setup`, `/enable`, `/verify`, `/disable`, `/recovery-codes`, and `GET /api/auth/2fa/status`.
- **Speed** — responses are gzipped (the app's scripts download at about a quarter of their size), the public pages (landing, privacy, terms) use pre-built Tailwind (`frontend/css/site.css`) instead of the in-browser CDN compiler
- **Inviting people** — anyone can be invited by email from 👥 Share, or straight away from New Project ("Invite people", several emails at once, with a role).
  - **People without an account** get an email with a link that opens sign-up with their address filled in (`/app?join=<email>`). The invite is held in `project_email_invites` until that email signs up (by password or Google), then it becomes an ordinary pending invite for them to accept.
  - **Share list:** waiting invites show there and the owner can cancel them (`DELETE /api/projects/:id/email-invites` with `{ email }`).
- **Project templates** — New Project opens with a gallery of six ready-made plans (land a new job, pass an exam, launch a side project, move home, plan an event, run a first 10K). One tap creates the whole plan dated from today: phases, tasks, targets and which tasks wait on which, in one transaction (`backend/templates.js`; `GET /api/projects/templates`, `POST /api/projects/from-template` with `{ templateId, startDate?, title? }`)
- **Undo** — deleting a task (or several) happens at once with an Undo button in the toast for 8 seconds, instead of an "are you sure?" first. It all goes to Trash, so Undo just restores it. Deleting a project still asks first, and offers Undo too
- **Calendar feed** — Settings → "Your tasks in your calendar" gives a private link to subscribe to in Google Calendar, Outlook or Apple Calendar (with one-tap buttons). Every task with a due date is an all-day event that keeps itself up to date, marked ✅ when done. The link carries a revocable token instead of a sign-in, since calendar apps can't sign in, and "Reset link" retires the old one (`GET /calendar/<token>.ics`, `GET /api/calendar/feed`, `POST /api/calendar/feed/reset`; tokens in `calendar_feeds`)
- **Costs** use the currency chosen in Settings everywhere
- **Progress reports** — 📄 Report on a project's header (or ⋯ → Progress report, or the palette) opens a report on that project or goal. It shows:
  - the schedule status (ahead, on track or behind, by how many points against where the dates say it should be) and a forecast finish from the last two weeks' pace
  - a plain-English summary
  - tiles for done, in progress, overdue and days left
  - every phase with a progress bar and status, and a timeline of the phases with today marked
  - what's recently done and coming up, what's overdue, open and cleared blockers, and tasks waiting on others

  It downloads as a PDF (headless Chromium), prints, goes by email, or shares as a **live read-only link** (`/r/<token>`, not indexed) that its owner or an editor can turn off at any time. Anyone who can see the project can view the report (`backend/reports/progress.js`; `GET /api/reports/projects/:id/progress`, `.html` and `.pdf`; `GET`/`POST`/`DELETE /api/reports/projects/:id/share`)
- **Design** — the house style is "Calm Bento with a quest layer", chosen from a Dribbble-led comparison of four directions:
  - **Planning:** solid, quiet surfaces (an #F4F5F7 ground, white cards with hairline borders and generous radii, a light sidebar), set in Plus Jakarta Sans.
  - **Game:** drawn in a brighter, rounder style in Nunito (streak and level pills, quest chips, the navy focus card with stage segments and ▶ Play).
  - **Dashboard:** greeting and date, a ⌘K command bar with the assistant beside it, the focus goal (the project with the soonest open due date, its schedule status, next stop, Report and Play), today's quests, "Up next" tasks to tick off in place (gates respected), and this week against last.
  - **Phones** get a bottom tab bar (Home, Planner, Journey, Actions, More).
  - Every page is checked at 390px and 360px wide with nothing scrolling sideways: the header search shortens to "Search…", the Settings tabs stop at the screen edge, project task cards keep their text clear of the priority bar, the Rewards buttons drop under their heading, the Actions counts line up, and buttons like Mark done and Move to stay on one line.
  - **Website:** the public site uses the same light style.
  - **Dark mode** uses solid surfaces too.
- **The game layer** (`backend/journey.js`, `frontend/js/gameui.js`, `frontend/js/sfx.js`):
  - **XP:** finishing a task pays XP by priority, plus a bonus for finishing before the due date. Beating a blocker pays 5 XP per enemy (up to 20), only the first time it's beaten.
  - **Ranks:** levels carry a rank title, from 🌱 Rookie through 🧭 Explorer, 🔥 Trailblazer, 🏅 Champion and 👑 Legend to 🐉 Mythic. Levelling up plays a full-screen moment with a fanfare (and a "new rank" ribbon when the title changes).
  - **Daily quests:** three a day. "Finish a task" is always one, and two more rotate by date (finish 3 tasks, a High priority task, beat a blocker, finish early). Progress is read from what really happened today, and finishing all three pays +30 XP once a day. They show on the dashboard, as a 🎯 badge on the Journey, and in the Trophy Case.
  - **Achievements:** 21 in groups (tasks, blockers, projects, habits, quests, levels), such as Early Bird, Chain Reaction, Comeback Kid, Master Builder and Habit Hero.
  - **Feedback:** "+XP" chips float up when something pays.
  - **Sound:** short synthesised sounds (Web Audio, no files) and phone vibrations for finishing, knockouts, level-ups, achievements and quests, switched off with 🔊 on the Journey or Settings → Game sounds.

  Everything is awarded on the server from real events only, so none of it can be farmed by tapping.
- **Command palette** — ⌘K / Ctrl+K (or the ⌘ button in the top bar, for phones) opens one box to do anything, like Linear or Raycast: jump to any page, project or task, run an action (new task, new project or template, assistant, week in review, dark mode, switch Journey stage), or type anything and add it as a task ("call the bank tomorrow" sets the due date) or hand it to the assistant. Arrow keys and Enter (`frontend/js/palette.js`)
- **Getting started slides** — until a new account finishes its first task, the dashboard's This week card plays one slide per feature (plan with the assistant, Start my day, the Journey, blockers, Your why, rewards), each with a button that opens it. The home page plays the same slides. Both read the `tour` list in `frontend/data/product.json`, so a feature is described once
- **My week in review** — 🎬 My week on the dashboard (or the palette) plays a Wrapped-style story of the last seven days: tasks finished against the week before, the best day, blockers beaten, the streak, the project that moved most and what's coming up, ending on a summary ("On a roll 🔥") that shares as a 1080×1350 image (the phone's share sheet, or a download). Tap or arrow keys to move, Esc to close (`frontend/js/recap.js`)
- **Keyboard shortcuts** — `/` search, `n` new task (in the open project), `a` assistant, `?` lists them, `Esc` closes
- **Calendar weeks** start on Monday, or on Sunday where the browser's locale expects it (US, Canada and a few others)
- **Project sharing & collaboration** — Google-Sheets/Drive-style: a project's owner invites another existing account by email (👥 Share, on any project or its sub-folder — sharing always covers the whole tree, and a sub-folder created by a collaborator is still owned by the tree's real owner, not whoever created it) rather than joining a company-wide workspace, choosing a role at invite time — **Viewer** (read-only), **Commenter** (read + comment/chat, no edits), or **Editor** (full working access — create/edit/delete tasks, edit project details, same as the owner short of deleting the project or managing who's on it). The owner can change anyone's role later from the Share panel, which shows each collaborator with a live-ish presence dot (green if active in the last 5 minutes, from a lightweight heartbeat — not a live socket connection). A shared project shows a "👤 Shared by X" badge (on its card and its detail page); the owner's own project cards instead show "👥 Shared with N" or "🔒 Private" so it's obvious at a glance which of your own projects anyone else can see. All Projects has an **All / My Projects / Shared with Me / Shared by Me** filter for the same reason. Tasks can be **assigned** to anyone with access — an initial-avatar badge shows on the task table row, task detail panel, Gantt row, and Kanban card — and carry a **comment thread** for async updates, with a "💬 n" count badge on the task table row, Gantt row, and Kanban card so a comment left by a teammate is actually noticeable instead of only visible once you open the task. Comments (and project chat messages) support **@mentions** — typing "@" opens a picker of people with access, and picking one inserts their name, later highlighted wherever it's shown — and **replies**: a "↩" on any comment or message quotes it above your response, both in the task's comment thread and in project chat. A pending invite shows as a banner + inbox on the invitee's next login, with Accept/Decline. A collaborator (any role) can remove themselves from someone else's project at any time — **🚪 Leave Project** in that project's "⋯" menu — no owner approval needed, the flip side of the owner's own 🗑️ Delete in the same menu (the two are mutually exclusive: the owner can't leave their own project, a collaborator can't delete it)
- **Project chat** — a running, project-wide discussion (separate from per-task comments) reachable via a "💬 Chat" button on any shared project's detail page, or from the **Chats** nav item — a WhatsApp-style inbox listing every project you've shared or been shared, most recently active first, each row showing a preview of its latest message (only projects with someone else on them show up here; a solo project has no one to chat with). Messages render as WhatsApp/iMessage-style bubbles — your own on the right in teal, everyone else's on the left in gray with their name and an initial avatar (repeated only when the sender changes, not on every consecutive message) — so who sent what is obvious at a glance instead of reading a "(you)" label. The **Chats** nav item itself shows an unread badge — the total count of new messages across every project chat since you last checked, like an unread-mail counter; opening the inbox (or the notification bell) clears it. Polled every few seconds while open so new messages show up without a manual refresh — no socket connection, same lightweight approach as presence. A 👥 icon in the chat panel's own header opens the same Share panel used on the project's detail page — invite someone by email and set their role (Viewer/Commenter/Editor) right from the conversation, no need to back out to the project first. Viewers can read it; Commenters and Editors can post; anyone can delete their own message, the owner can delete any of them. Messages are grouped under Today / Yesterday / the date. The message box grows as you type (Enter sends, Shift+Enter for a new line), and one **+** button holds Photo or video (the camera on phones), File and Email this to the team. Any message can be emailed out — "Email this to the team" from the + menu (opt-in per message, not a setting) emails it to every accepted collaborator, plus anyone extra typed into an optional CC field, even people with no Waypoint account. Uses the same Resend-based email setup as the daily digest — silently unavailable until `RESEND_API_KEY` is set, with a toast saying so if you try it before then
- **Media & file sharing in chat and comments** — the project chat's **+** menu (or pasting a photo, or dropping a file anywhere on the chat, with a thumbnail before you send) and the task comment box's 📎 attach an image, video, PDF, Office doc, or plain text/CSV file (25MB max) to a message or comment. Images show as an inline preview, video as an inline player, everything else as a download chip. Files are stored under a random, unguessable name and served through an authenticated endpoint that checks the requester actually has access to that project — not a public static folder — so a link to someone's attachment is useless to anyone without access. Anyone who can comment can attach a file; a Viewer can see attachments others posted but can't add their own
- **Notifications** — a 🔔 bell in the topbar with a badge count, covering pending invites, tasks newly assigned to you, and new project chat / task comment activity since you last checked. Opening the dropdown clears the badge (except invites, which stay listed until accepted or declined) and clicking an item jumps straight to it — the project's chat, the task's detail panel, or the invites inbox
- **Optional card fields (Gantt + Kanban)** — the "⋯ More" menu in the Gantt/Kanban toolbar lets you choose which extra details show on task rows/cards: Assignee, Priority, Tags, Checklist progress, Cost, and Schedule status. Schedule status is derived, not stored — 🔴 Delayed (past its due date, not done), 🟢 On Track (has a due date, not overdue), or ✅ Done — and also rolls up per-project on the Gantt group header row. Off by default for the denser ones (Priority text, Cost) since priority already shows as a color, and cost isn't relevant to every project — on for the rest, matching how they already looked. Applies to both views at once and remembers your choice
- **Global search** — a search box in the topbar, on every page, live-searches project and task titles as you type (debounced, 2+ characters) and jumps straight to whichever result you pick
- **🎙️ Waypoint assistant** — one chat that can plan a new goal or change the project you're in: add, edit, move or delete tasks (a deleted task goes to Trash, where it can be restored), add phases, manage blockers, set or clear a task's progress target and count ("track 20 pages"), and add or remove a task's predecessors ("make Testing wait for Build"; loops are never proposed). Every change is shown as a list to tick and approve first; nothing changes on its own. Type, attach a plan, or tap the mic: while it's listening, a Shazam-style panel shows a pulsing mic orb with moving sound bars and your words as they're heard, and the mic button glows red (tap either to stop). Wireless earbuds (AirPods and the like) only switch their mic on when a page opens it, which takes a second, so the mic is opened first ("Connecting your microphone…") and kept open while listening (released first on iPhone/iPad, which allow only one); listening carries on through short pauses, quietly retries once if nothing was heard at the start, and a failure says why (permission blocked, no microphone found, nothing heard, offline) instead of a generic error. Conversations are saved (`GET/PUT/DELETE /api/ai/conversations[/:id]`, private to each user; attached files are never stored, only their names), so reopening the assistant picks up your last chat for that project, **🕘 History** lists every chat with its project to carry on any of them, and **＋ New** starts fresh. Open it from the Dashboard, All Projects, a project page (✨ Assistant), or **✨ Ask AI** on the project and task edit windows and the task details panel; from a task it focuses on that task ("🎯 About the task …", so "this task" means it) with one-tap suggestions like "Split it into smaller tasks", "Push the due date back a week", "Set a target count for it", "Make it wait on another task" or "Delete this task". A sub-folder's task opens the assistant on its top-level project, where the whole plan lives
- **New version notice** — a tab left open keeps running the code it loaded, so after a deploy it would quietly show the old behaviour. Every few minutes (and whenever the tab comes back into view) the app asks `GET /api/version` which build is live (the deployed commit on Railway, `RAILWAY_GIT_COMMIT_SHA`), and if it's changed a small "✨ A new version of Waypoint is ready — Reload" notice appears. Pages, scripts and styles are also served with `Cache-Control: no-cache`, so a reload always picks up the new build
- **Back navigation** — a ← button in the topbar (shown only once there's somewhere to go back to) retraces your actual click trail across the whole app — project detail, Gantt, Calendar, Actions, etc. — rather than being wired page-by-page; since the app has no browser routing, this is an in-memory history stack pushed on every real navigation
- **Recurring tasks** — a task can repeat Daily/Weekly/Monthly; marking one Completed automatically creates the next occurrence with dates shifted forward
- **Onboarding wizard** — name, first project, and an optional Google Drive connection on first login
- **Projects & sub-folders** — one level of nested sub-projects (e.g. "UK Career Goals" → "Cloud Engineering Goals"), each individually editable. A project's "⋯" menu has **⧉ Duplicate Project** — makes an independent copy of the whole tree (the project, its sub-folder, and all their tasks, checklists, and tags) under your own account, ready to edit freely. It doesn't touch the original or its sharing at all, so anyone with access — even a Viewer — can duplicate; the new copy always starts out unshared, with task assignees dropped since the new project has no collaborators yet
- **Project types** — Career, Health & Fitness, Learning, Business, Home & Family, Relationships, Personal Growth, Hobbies & Creative, or Travel — pick whichever fits, purely for clarity. Every type gets the same full task list (add/edit/delete, filters, KPIs); it's an organizational label only, with no functional difference between types
- **Tasks** — status, priority, start/due dates, notes; "Add to Google Calendar" per task (task table and Gantt chart both). The project detail task table supports **bulk actions**: check any rows (or "select all") to reveal a bar for setting Status or Priority across all of them at once, or moving them all to Trash in one go. A **⧉ Duplicate** action (task table row, Gantt row, Kanban card, and the task detail panel) makes an independent copy in the same project — same fields, checklist, and tags, titled "(Copy)" — without carrying over its comments; requires edit access, same bar as creating a task
- **Checklists (subtasks)** — any existing task can have a checklist of its own lightweight items (add, check off, delete), edited from the task modal. A "n/m" progress badge shows on that task's row in the project table and its Kanban card once it has any items
- **Progress target** — for a repetitive goal made of identical units (e.g. "20 mock tests" rather than 20 distinctly-named checklist items), set an optional numeric target + unit label on a task from its edit modal. Shows as a progress bar with a "+1" button (task table row, Gantt row, Kanban card, and the task detail panel) — one tap logs a unit instead of typing out 20 separate checklist entries. Hits the target and the task auto-completes (and un-completes itself if a correction drops the count back below target); requires edit access, same bar as everything else that changes a task
- **Tags** — custom, per-account, colored labels (beyond the built-in Priority/Status) attachable to any task from its edit modal — pick existing ones or create a new one (name + color) inline. Shown as small colored chips on the task table row and its Kanban card, and filterable in the project detail task table alongside Status/Priority
- **The key** — a Key button on the Planner (Gantt and Kanban) and the Calendar opens a panel explaining every mark on that view, each shown as it's drawn with words beside it: goal colours, faded bars for done tasks, priority outlines, diamonds for due-date-only tasks, phase bars, today and goal-start lines, dependency arrows (solid when the earlier task is done, dashed while waiting), status dots, blocker and waiting badges, schedule pills, overdue and done marks on the calendar. Open or closed is remembered (`frontend/js/plannerKey.js`)
- **Sign in** — a page of its own: what Waypoint does and a real screenshot beside the form on a computer, a short header on a phone, a heading for each step (Welcome back, Create your account, Reset your password, Two-step sign-in)
- **Gantt chart** — with a **Kanban view** alongside the timeline (a "🗂️ Timeline / 📋 Kanban" toggle, remembered next time — the page heading and topbar title switch between "Gantt Chart" and "Kanban Board" too): three columns by status, drag a card between columns to change its status. An overdue card's due date shows in red with a 🔴, same as the rest of the app — the card visibly lifts and follows the cursor (a floating copy, tilted and shadowed) rather than just fading in place, same drag feel as the timeline's bars and rows, and works with touch too, a phone, tablet, or the Android app, not just a mouse — on touch, a brief hold (~300ms) starts the drag, so an ordinary swipe still scrolls the column instead of picking up whatever card your finger landed on. Cards can be **sorted** — by Due Soon or Starting Soon (each buckets by urgency: overdue/already-should-have-started, then today, then this week, then everything else, so it actually answers "what do I need to work on or start today or this week" instead of a flat chronological list), by Priority, or by Recently Added — and **filtered by priority**, both remembered next time. A "+" per column adds a task straight in with that status preselected, and the same hover-revealed 📅/🗑️ actions as everywhere else. Respects the same project filter as the timeline. Full CRUD directly from the chart either way: a "+ Add Project" button in the toolbar, a hover-revealed "+" on each project row to add a task straight into it (no need to pick a project from a dropdown), and a hover-revealed 🗑️ on both project and task rows to delete either (deleting a project cascades to its tasks, with a confirmation first). Task rows can also be manually reordered — drag the hover-revealed ⠿ handle up or down within a project to set your own order, which persists (and is reflected in that project's task table too, since both share the same order). Frozen columns (Task/Project, Status, Start, Due, Duration) can be individually widened or narrowed by dragging their right edge, Excel-style — handy for a long task title that's otherwise clipped, and the widened columns carry through to Print/PDF too, not just the on-screen view. Remembered next time; a "↔️ Reset Column Widths" entry in the "⋯ More" menu puts them back to default. A "Wrap task text" toggle in the same menu (off by default, so rows stay compact) lets a task or project title that's still too long for its column wrap onto multiple lines instead of ending in an ellipsis — rows grow to fit. Print/PDF is a genuine mirror of the screen: whichever way the toggle is set, that's how titles print too. Printing also trims the timeline itself to whatever's actually shown — its earliest task's start through its latest task's due date (anchored to the project's own start date instead when one is selected in the filter dropdown) — no padded months of blank chart before or after it, the way the normal on-screen view intentionally shows for browsing. The printed width always fits the page too — the same minimum-column-width rule that keeps a wide date range readable on a scrolling screen is dropped for print, so the date columns shrink to fit instead of running off the edge and getting cut off (that same on-screen-only rule is also what previously could, on a narrow/mobile print, incorrectly carry over the mobile layout's dropped Start/Due/Duration columns into the printout too — now screen-only, so print always keeps every column unless told otherwise). A "Print columns" section in the same menu (Timeline-only) lets Status/Start/Due/Duration each be left out of Print/PDF individually — Task/Project always prints — freeing that space for the timeline instead of leaving a blank gap; on-screen is unaffected either way. Also: drag-to-move / drag-to-resize bars (drag a bar to move it, either end to change its start or due date, a diamond to move its due date, or a folder's summary bar to shift every task in it; with a mouse, or on a phone or tablet after a short press so an ordinary swipe still scrolls; the bar snaps to whole days, a label above it shows the new dates while it moves, grips show on its ends on hover and always on touch screens, and the toast afterwards has Undo; a plain click or tap opens the task), collapsible groups by project — individually, or all at once with a single **Collapse All** / **Expand All** toggle button (a project's sub-folders always stay grouped directly beneath it, never scattered alphabetically among unrelated projects), Week/Month/Year zoom, a project filter dropdown to zoom into a single project's tasks, frozen Task/Status/Start/Due/Duration columns (Status is an inline dropdown, same as the task table — no need to open a task just to mark it done) with a horizontally scrolling timeline, and a single **⋯ More** menu (shared with Kanban) bundling **Print/PDF** (the browser's native print, with a stylesheet that un-freezes the columns — available in both Timeline and Kanban, printing whichever one is currently on screen), **Export Image** (a server-side headless-browser screenshot of the live Gantt chart specifically — more reliable than a client-side canvas library, which clips text in this chart's CSS Grid rows; Kanban doesn't have an image-export equivalent yet, just Print/PDF), and the optional card-fields checkboxes below — kept off the main toolbar so it doesn't turn into a wall of buttons. On narrow/mobile screens every column is still there but only the task name stays frozen: Status, Start, Due and Duration scroll with the timeline (swipe right for them, left for the bars), the timeline's periods are wider so bars stay readable, and the chart opens on today with the bars in view
- **Start my day** — the Today card's one button opens three short steps. **Your day**: today's tasks as a timetable, each with a start time and a length (15 minutes to 2 hours), worked out from when you start; move tasks earlier or later, change a length, add one from your list or a new one, have the day read out, or plan it with the assistant. **Blockers**: the blockers already on today's tasks, and room to add one. **Music**: pick something to play or skip. Then today's quote from Your why fills the screen for a moment and fades, and the first task starts as a focus session of its own length; each one you finish hands you the next. The plan is saved per day on the server (`backend/dayPlan.js`, `/api/day/plan/:date`), so a plan made last night or on another device is waiting. **Good-morning notification** (Settings → Notifications): at your wake-up time, in your own time zone, a push saying "Good morning, your day is ready" that opens Start my day. The dashboard's Today card is kept light: the greeting, today's plan with the time of what's next, and the button
- **Today's road and the Pacer** — once today has a plan, the focus timer grows into a panel: the timer, then today's road (a stop per task, You moving as you finish them, and a Pacer moving with the clock along the times you planned, like a pacer in a race) with a line saying how far ahead of or behind plan you are, then a music row (what's playing, pause, next, and Add music: a quick search that saves the pick to Your why and plays it). Finishing early always counts as ahead; within five minutes either way is level. Minimised, the timer shows a dot: green ahead of plan, teal on plan, amber behind. The same strip sits on the dashboard's Today card, and Full view lays the day out as a list of stops with times, blockers and where the Pacer is. Full view has two modes, Road (that list) and Game (the day drawn as a Journey world, one stop per task, You and the Pacer racing on it, with its own world picker and 2D/3D switch above the list); the choice is remembered, and Game is the default when the game layer is on. Each stop's circle in Full view is its tick box: tick it to finish the task there (in Game view the character walks on to the next stop; with blockers still in the way the "Not yet" card opens to clear them first), or tick a done one to reopen it. ## Tech stack

- **Backend**: Node.js (22+) + Express, `better-sqlite3` (SQLite), `express-session` backed by `better-sqlite3-session-store` (sessions survive redeploys), `bcryptjs`
- **Frontend**: Vanilla JS (plain scripts, no bundler) + Tailwind CSS built ahead of time (`npm run build:css`, config in `tailwind.config.js`); line icons from Lucide (`frontend/js/icons.js`)
- **Payments**: Stripe's REST API with `fetch` (no SDK); webhook signatures checked by hand
- **Exports**: `exceljs` (Excel), `puppeteer-core` (PDF/image reports), `googleapis` (Drive/Sheets)
- **AI**: `@anthropic-ai/sdk` (Claude, tool-use for structured output — task prioritization and file-to-project extraction), `multer` (file uploads)

ElevenLabs (elevenlabs.io → Profile → API keys) is used when both are set; OpenAI's speech model otherwise (`OPENAI_TTS_MODEL`, default `gpt-4o-mini-tts`). Each person gets up to `VOICE_DAILY_CHARS` (default 12000) characters read a day, repeated lines are cached, and the device voice takes over when it's not set up, the allowance is used or the service doesn't answer (`backend/voice.js`) |
| `YOUTUBE_API_KEY` | No | YouTube music search (full songs that play in the app). A Google Cloud API key with the YouTube Data API v3 on; the free allowance is about 100 searches a day. "Connect YouTube" reuses the Google OAuth client above: add `<APP_URL>/api/music/youtube/callback` as a redirect URI and the `youtube.readonly` scope |
| `VAPID_CONTACT_EMAIL` | No | Push Reminders need no setup at all — the server generates and stores its own VAPID keypair on first use. This is just a contact address push services may use if your server misbehaves. Defaults to `admin@example.com` |

```bash
npm run dev       # auto-restart on change (nodemon)
```

Check it:

## Deploying

A `Dockerfile` is included and is the recommended path — it installs Chromium (needed for PDF/image exports) and runs it with `--no-sandbox`, which containers require since they run as root with no sandbox namespace available. A `Procfile` (`web: node backend/server.js`) is also included for buildpack-style platforms, but without Chromium pre-installed those platforms will show PDF/image export errors unless you separately configure a Chromium buildpack and set `PUPPETEER_EXECUTABLE_PATH`.

### Railway (recommended)

1. Create a new project from this repo — Railway detects the `Dockerfile` automatically.
2. **Attach a volume**: mount it at `/data`, then set `DB_PATH=/data/lifetracker.sqlite`. Without this the SQLite database (and every session) is wiped on every redeploy.
3. Set environment variables: `SESSION_SECRET` (generate one — see the table below), `NODE_ENV=production`, `APP_URL` (your Railway domain, once you have it), and `ANTHROPIC_API_KEY`/`GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET`/`GOOGLE_REDIRECT_URI`/`MICROSOFT_CLIENT_ID`/`MICROSOFT_CLIENT_SECRET`/`RESEND_API_KEY` if you want those features live. Don't set `PUPPETEER_EXECUTABLE_PATH` — the Dockerfile already does.
4. Once Railway gives you a domain, if you're using Google features, go back to Google Cloud Console and add **both** `https://<your-domain>/api/drive/callback` and `https://<your-domain>/api/auth/google/callback` as Authorized redirect URIs on the OAuth client, and update `GOOGLE_REDIRECT_URI` to the first one.
5. **Off-site backups**: create a Cloudflare R2 bucket (or S3), make an API token that can write to it, and set the `BACKUP_S3_*` variables. Add a lifecycle rule to delete copies after 30 days. Restore by downloading `db/lifetracker-<date>.sqlite.gz`, unzipping it, and putting it at `DB_PATH` with the service stopped. Uploaded files are under `uploads/` in the bucket and go back in the `uploads` folder beside it.
6. **Health and uptime**: `railway.json` tells Railway to wait for `/api/health` (which checks the database) before switching traffic to a new deploy, and to restart the service if it crashes. Point a free uptime monitor (UptimeRobot, Better Stack) at `https://<your-domain>/api/health` so you're emailed when the site is down.
7. **Error tracking**: set `SENTRY_DSN` (a free Sentry project) so crashes reach you. Failed nightly backups are reported there too.
8. **Check it**: the owner **Metrics** page opens with a **Service** list: data volume, off-site backups, the last backup and whether it went off-site, error tracking, email and payments. Each one that's off says which variable to set.

### Any other host

1. Set `SESSION_SECRET` and `NODE_ENV=production`.
2. Attach persistent storage and set `DB_PATH` to a file inside it — otherwise the SQLite database is wiped on every redeploy.
3. Make sure a Chromium-family browser is available and set `PUPPETEER_EXECUTABLE_PATH` to it — used for PDF/image reports and the Gantt chart's image export. Building from the included `Dockerfile` handles this automatically.
4. Set the Google OAuth variables only if Drive backup / Sign in with Google should be enabled — see the redirect URI note above.

Sessions are stored in the same SQLite database (`better-sqlite3-session-store`) rather than in memory, so — as long as `DB_PATH` points at persistent storage — logins survive redeploys instead of forcing everyone to sign in again each time.

## iPhone

An APK only installs on Android — iOS can't sideload one, and there's no workaround for that. Instead, the web app itself is set up for Safari's "Add to Home Screen": with the `apple-mobile-web-app-*` meta tags and `apple-touch-icon` in `frontend/index.html`, that gives a real full-screen app icon on the home screen with no browser chrome, entirely free (no Mac, no Apple Developer account, no Xcode). A proper native iOS app (App Store or sideloaded) would additionally need a Mac with Xcode and, to distribute it at all, a $99/year Apple Developer account.

## Android app

`mobile/` is a thin [Capacitor](https://capacitorjs.com) wrapper — a real installable Android app whose WebView just points at the live Railway deployment (`mobile/capacitor.config.json` → `server.url`). There's no separate mobile codebase to maintain: any change pushed and deployed to Railway shows up in the app immediately, no rebuild needed. A rebuild is only needed for things baked into the native shell (app name/icon, the URL it points at).

Not published to the Play Store (personal use only) — it's installed by sideloading the APK directly. The app icon (`frontend/icons/`, generated from a single SVG) is shared between the web manifest and the Android launcher icon (both the flat pre-Android-8 icon and the adaptive icon's foreground/background layers).

The Android `appId` is still `com.lifetracker.app`, left over from before the app was renamed to Waypoint — intentionally not changed, since Android treats a different `appId` as a different app entirely rather than an update to the one already installed. Changing it is possible any time (edit it in `mobile/capacitor.config.json` and `mobile/android/app/src/main/res/values/strings.xml`, then rebuild), it would just mean reinstalling on any phone that already has the old one.

**Rebuilding the APK** (requires a JDK 21 and the Android SDK command-line tools — set `JAVA_HOME` and `ANDROID_HOME` first):

```bash
cd mobile
npx cap sync android        # only needed after changing capacitor.config.json
cd android
./gradlew assembleDebug     # gradlew.bat on Windows
```

The APK is written to `mobile/android/app/build/outputs/apk/debug/app-debug.apk`. To install it on a phone: enable "Install unknown apps" for whatever app you use to open the file (e.g. Files, Chrome), transfer the APK over (USB, email to yourself, cloud drive), and tap it — or with the phone connected via USB and USB debugging on, `adb install app-debug.apk`.

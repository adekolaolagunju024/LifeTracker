# Waypoint

A general-purpose personal goal tracker — Career is just one of the built-in project types; use it for any goal, in any area of life. Multi-user and collaborative, self-hosted, no external dependencies required to run locally.

## Features

- **Accounts** — email/password registration and login, sessions scoped per user (`express-session`), an optional "Sign in with Google" (finds-or-creates an account by email), a "Keep me signed in" toggle (persistent 30-day session vs. a session-only cookie cleared when the browser closes), browser-native password-save support (real `<form>` submits + the Credential Management API), a "Forgot password?" flow (no email service required — the reset link is logged to the server console rather than emailed, so it's the account owner reading their own logs), and self-service permanent account deletion from Settings (password-confirmed; every project/task row cascades with it)
- **Project sharing & collaboration** — Google-Sheets/Drive-style: a project's owner invites another existing account by email (👥 Share, on any project or its sub-folder — sharing always covers the whole tree, and a sub-folder created by a collaborator is still owned by the tree's real owner, not whoever created it) rather than joining a company-wide workspace, choosing a role at invite time — **Viewer** (read-only), **Commenter** (read + comment/chat, no edits), or **Editor** (full working access — create/edit/delete tasks, edit project details, same as the owner short of deleting the project or managing who's on it). The owner can change anyone's role later from the Share panel, which shows each collaborator with a live-ish presence dot (green if active in the last 5 minutes, from a lightweight heartbeat — not a live socket connection). A shared project shows a "👤 Shared by X" badge (on its card and its detail page); the owner's own project cards instead show "👥 Shared with N" or "🔒 Private" so it's obvious at a glance which of your own projects anyone else can see. All Projects has an **All / My Projects / Shared with Me / Shared by Me** filter for the same reason. Tasks can be **assigned** to anyone with access — an initial-avatar badge shows on the task table row, task detail panel, Gantt row, and Kanban card — and carry a **comment thread** for async updates. A pending invite shows as a banner + inbox on the invitee's next login, with Accept/Decline. A collaborator (any role) can remove themselves from someone else's project at any time — **🚪 Leave Project** in that project's "⋯" menu — no owner approval needed, the flip side of the owner's own 🗑️ Delete in the same menu (the two are mutually exclusive: the owner can't leave their own project, a collaborator can't delete it)
- **Project chat** — a running, project-wide discussion (separate from per-task comments) reachable via a "💬 Chat" button on any shared project's detail page, or from the **Chats** nav item — a WhatsApp-style inbox listing every project you've shared or been shared, most recently active first, each row showing a preview of its latest message (only projects with someone else on them show up here; a solo project has no one to chat with). Messages render as WhatsApp/iMessage-style bubbles — your own on the right in teal, everyone else's on the left in gray with their name and an initial avatar (repeated only when the sender changes, not on every consecutive message) — so who sent what is obvious at a glance instead of reading a "(you)" label. The **Chats** nav item itself shows an unread badge — the total count of new messages across every project chat since you last checked, like an unread-mail counter; opening the inbox (or the notification bell) clears it. Polled every few seconds while open so new messages show up without a manual refresh — no socket connection, same lightweight approach as presence. A 👥 icon in the chat panel's own header opens the same Share panel used on the project's detail page — invite someone by email and set their role (Viewer/Commenter/Editor) right from the conversation, no need to back out to the project first. Viewers can read it; Commenters and Editors can post; anyone can delete their own message, the owner can delete any of them. Any message can also be emailed out — an "✉️ Also email this to the team" checkbox on send (opt-in per message, not a setting) emails it to every accepted collaborator, plus anyone extra typed into an optional CC field, even people with no Waypoint account. Uses the same Gmail SMTP setup as the daily digest — silently unavailable until `GMAIL_USER`/`GMAIL_APP_PASSWORD` are set, with a toast saying so if you try it before then
- **Status** — a WhatsApp-style Status tray at the top of each project's chat: post a photo/video with an optional caption (or text-only), visible to that project's team for 24 hours, then it disappears automatically — no manual cleanup. Shown as a row of avatar rings; tapping one opens a full-screen story-style viewer (progress bar, tap left/right to step through, swipe area doubling as prev/next). Viewers can look but not post; Commenters and Editors can post; anyone can delete their own status early, the owner can delete anyone's
- **Media & file sharing in chat and comments** — a 📎 button on both the project chat and the task comment box attaches an image, video, PDF, Office doc, or plain text/CSV file (25MB max) to a message or comment. Images show as an inline preview, video as an inline player, everything else as a download chip. Files are stored under a random, unguessable name and served through an authenticated endpoint that checks the requester actually has access to that project — not a public static folder — so a link to someone's attachment is useless to anyone without access. Anyone who can comment can attach a file; a Viewer can see attachments others posted but can't add their own
- **Notifications** — a 🔔 bell in the topbar with a badge count, covering pending invites, tasks newly assigned to you, and new project chat / task comment activity since you last checked. Opening the dropdown clears the badge (except invites, which stay listed until accepted or declined) and clicking an item jumps straight to it — the project's chat, the task's detail panel, or the invites inbox
- **Optional card fields (Gantt + Kanban)** — the "⋯ More" menu in the Gantt/Kanban toolbar lets you choose which extra details show on task rows/cards: Assignee, Priority, Tags, Checklist progress, Cost, and Schedule status. Schedule status is derived, not stored — 🔴 Delayed (past its due date, not done), 🟢 On Track (has a due date, not overdue), or ✅ Done — and also rolls up per-project on the Gantt group header row. Off by default for the denser ones (Priority text, Cost) since priority already shows as a color, and cost isn't relevant to every project — on for the rest, matching how they already looked. Applies to both views at once and remembers your choice
- **Global search** — a search box in the topbar, on every page, live-searches project and task titles as you type (debounced, 2+ characters) and jumps straight to whichever result you pick
- **Back navigation** — a ← button in the topbar (shown only once there's somewhere to go back to) retraces your actual click trail across the whole app — project detail, Gantt, Calendar, Actions, etc. — rather than being wired page-by-page; since the app has no browser routing, this is an in-memory history stack pushed on every real navigation
- **Recurring tasks** — a task can repeat Daily/Weekly/Monthly; marking one Completed automatically creates the next occurrence with dates shifted forward
- **Onboarding wizard** — name, first project, and an optional Google Drive connection on first login
- **Projects & sub-folders** — one level of nested sub-projects (e.g. "UK Career Goals" → "Cloud Engineering Goals"), each individually editable. A project's "⋯" menu has **⧉ Duplicate Project** — makes an independent copy of the whole tree (the project, its sub-folder, and all their tasks, checklists, and tags) under your own account, ready to edit freely. It doesn't touch the original or its sharing at all, so anyone with access — even a Viewer — can duplicate; the new copy always starts out unshared, with task assignees dropped since the new project has no collaborators yet
- **Project types** — Career, Health & Fitness, Learning, Business, Home & Family, Relationships, Personal Growth, Hobbies & Creative, or Travel — pick whichever fits, purely for clarity. Every type gets the same full task list (add/edit/delete, filters, KPIs); it's an organizational label only, with no functional difference between types
- **Tasks** — status, priority, start/due dates, notes; "Add to Google Calendar" per task (task table and Gantt chart both). The project detail task table supports **bulk actions**: check any rows (or "select all") to reveal a bar for setting Status or Priority across all of them at once, or moving them all to Trash in one go. A **⧉ Duplicate** action (task table row, Gantt row, Kanban card, and the task detail panel) makes an independent copy in the same project — same fields, checklist, and tags, titled "(Copy)" — without carrying over its comments; requires edit access, same bar as creating a task
- **Checklists (subtasks)** — any existing task can have a checklist of its own lightweight items (add, check off, delete), edited from the task modal. A "n/m" progress badge shows on that task's row in the project table and its Kanban card once it has any items
- **Progress target** — for a repetitive goal made of identical units (e.g. "20 mock tests" rather than 20 distinctly-named checklist items), set an optional numeric target + unit label on a task from its edit modal. Shows as a progress bar with a "+1" button (task table row, Gantt row, Kanban card, and the task detail panel) — one tap logs a unit instead of typing out 20 separate checklist entries. Hits the target and the task auto-completes (and un-completes itself if a correction drops the count back below target); requires edit access, same bar as everything else that changes a task
- **Tags** — custom, per-account, colored labels (beyond the built-in Priority/Status) attachable to any task from its edit modal — pick existing ones or create a new one (name + color) inline. Shown as small colored chips on the task table row and its Kanban card, and filterable in the project detail task table alongside Status/Priority
- **Gantt chart** — with a **Kanban view** alongside the timeline (a "🗂️ Timeline / 📋 Kanban" toggle, remembered next time — the page heading and topbar title switch between "Gantt Chart" and "Kanban Board" too): three columns by status, drag a card between columns to change its status. An overdue card's due date shows in red with a 🔴, same as the rest of the app — the card visibly lifts and follows the cursor (a floating copy, tilted and shadowed) rather than just fading in place, same drag feel as the timeline's bars and rows, and works with touch too, a phone, tablet, or the Android app, not just a mouse — on touch, a brief hold (~300ms) starts the drag, so an ordinary swipe still scrolls the column instead of picking up whatever card your finger landed on. Cards can be **sorted** — by Due Soon or Starting Soon (each buckets by urgency: overdue/already-should-have-started, then today, then this week, then everything else, so it actually answers "what do I need to work on or start today or this week" instead of a flat chronological list), by Priority, or by Recently Added — and **filtered by priority**, both remembered next time. A "+" per column adds a task straight in with that status preselected, and the same hover-revealed 📅/🗑️ actions as everywhere else. Respects the same project filter as the timeline. Full CRUD directly from the chart either way: a "+ Add Project" button in the toolbar, a hover-revealed "+" on each project row to add a task straight into it (no need to pick a project from a dropdown), and a hover-revealed 🗑️ on both project and task rows to delete either (deleting a project cascades to its tasks, with a confirmation first). Task rows can also be manually reordered — drag the hover-revealed ⠿ handle up or down within a project to set your own order, which persists (and is reflected in that project's task table too, since both share the same order). Frozen columns (Task/Project, Status, Start, Due, Duration) can be individually widened or narrowed by dragging their right edge, Excel-style — handy for a long task title that's otherwise clipped, and the widened columns carry through to Print/PDF too, not just the on-screen view. Remembered next time; a "↔️ Reset Column Widths" entry in the "⋯ More" menu puts them back to default. A "Wrap task text" toggle in the same menu (off by default, so rows stay compact) lets a task or project title that's still too long for its column wrap onto multiple lines instead of ending in an ellipsis — rows grow to fit. Print/PDF is a genuine mirror of the screen: whichever way the toggle is set, that's how titles print too. Printing also trims the timeline itself to whatever's actually shown — its earliest task's start through its latest task's due date (anchored to the project's own start date instead when one is selected in the filter dropdown) — no padded months of blank chart before or after it, the way the normal on-screen view intentionally shows for browsing. The printed width always fits the page too — the same minimum-column-width rule that keeps a wide date range readable on a scrolling screen is dropped for print, so the date columns shrink to fit instead of running off the edge and getting cut off (that same on-screen-only rule is also what previously could, on a narrow/mobile print, incorrectly carry over the mobile layout's dropped Start/Due/Duration columns into the printout too — now screen-only, so print always keeps every column unless told otherwise). A "Print columns" section in the same menu (Timeline-only) lets Status/Start/Due/Duration each be left out of Print/PDF individually — Task/Project always prints — freeing that space for the timeline instead of leaving a blank gap; on-screen is unaffected either way. Also: drag-to-move / drag-to-resize bars, collapsible groups by project — individually, or all at once with a single **Collapse All** / **Expand All** toggle button (a project's sub-folders always stay grouped directly beneath it, never scattered alphabetically among unrelated projects), Week/Month/Year zoom, a project filter dropdown to zoom into a single project's tasks, frozen Task/Status/Start/Due/Duration columns (Status is an inline dropdown, same as the task table — no need to open a task just to mark it done) with a horizontally scrolling timeline, and a single **⋯ More** menu (shared with Kanban) bundling **Print/PDF** (the browser's native print, with a stylesheet that un-freezes the columns — available in both Timeline and Kanban, printing whichever one is currently on screen), **Export Image** (a server-side headless-browser screenshot of the live Gantt chart specifically — more reliable than a client-side canvas library, which clips text in this chart's CSS Grid rows; Kanban doesn't have an image-export equivalent yet, just Print/PDF), a **Legend** toggle for the color/priority key and any project-start (🚩) badges (Timeline-only, off by default, remembered next time — reference info, not something you need every time you look at the chart), and the optional card-fields checkboxes below — kept off the main toolbar so it doesn't turn into a wall of buttons. On narrow/mobile screens the Start/Due/Duration columns drop out and the remaining columns narrow so the actual timeline bars are reachable after a short swipe instead of a very long one
- **Dashboard** — goal-agnostic on purpose: one combined stats hero (Total/Completed/In Progress plus the overall Goals Progress bar, merged into a single card rather than four separate ones) aggregates every project regardless of type. A distinctly-styled "💬 Chat with AI" card sits right below it — this is the actual landing page after login, so the AI chat entry point lives here, not just a click deeper on All Projects. "Projects at a Glance" shows the first few projects' live stats (tasks, done, an overdue count highlighted in red, progress) as cards, with a "View All Projects →" link rather than a second project-management surface (no view toggle, no "+ New Project" here — that action lives on All Projects and Gantt, its two natural homes). A one-line "⚡ Needs Attention" strip (overdue / high-priority-in-progress counts, or "All caught up 🎉") links straight into Actions rather than duplicating its full task list on the Dashboard too
- **Actions** — a live, auto-generated feed (not a maintained list) of Overdue, Due This Week, Starting This Week, and High-priority-in-progress tasks across every project; mark one done straight from the feed
- **Calendar** — every task laid out by due date (a project filter dropdown narrows it to one), in **Month**, **Week**, or **Year** view, with prev/next navigation (steps by month/week/year to match) and a "Today" button. Tasks are **drag-and-drop rescheduled** onto a different day — same ghost-follows-cursor drag feel as Kanban's drag-to-status, dropping onto a day cell instead of a column. Overdue tasks show in red, completed ones strike through, a day with more than the cap (3 in Month, 8 in Week) shows a "+N more" that expands in place, clicking a task opens its detail panel, and clicking an empty day opens Add Task with that day pre-filled as the due date. Year view is a read-only 12-mini-calendar overview (a dot per day with something due, red if overdue) — click a day to jump into Month view there
- **Daily digest** — a dismissible banner on login/reload if anything is overdue or due today, linking straight into Actions; shows at most once per day
- **Daily digest email** (optional) — a genuine outside-the-app notification: one email a day (07:00 server time) grouping Overdue / Due Today / Due Tomorrow tasks by project, sent via Gmail SMTP. Opt-in per account from Settings → Notifications; skipped automatically on a day with nothing to report, and skipped entirely (with a log line, not an error) if Gmail credentials aren't configured on the server
- **AI Insights** (optional) — a "✨ Analyze My Tasks" button on the Actions page sends your open tasks to Claude and gets back a prioritized focus list plus 2-4 suggested next-step tasks you can add with one click. Button copy sets expectations up front (time + that it uses your API credits) and shows a spinner while it runs
- **Create a Project with AI** (optional) — a "💬 Chat with AI" card right on the Dashboard (previously buried a click deeper inside All Projects) opens straight into a real back-and-forth conversation for someone who doesn't know how to break a goal into tasks yet. A 📎 button next to the message box attaches a `.xlsx`/`.pdf`/`.png`/`.jpg` to any message — same one merged chat, not a separate upload tab — and Claude treats its content as real context for the goal, pulling out tasks/dates already in it rather than re-asking for them. It asks a clarifying question or two (timeframe, scope, current progress) and proposes a project once it has enough, or straight away if the goal (or the attached file) is already specific. Lands on a review screen either way; every field is editable and nothing is created until you confirm. The plain "+ New Project" button remains the fully manual option with no AI involved
- **Google Drive backup** (optional) — connect a Google account to export data as JSON, Excel, Google Sheets, PDF, or image
- **Export / Import Data (JSON)** — Settings has a full account export (profile, projects, tasks) and a matching import that recreates it for the current user, remapping project/sub-folder ids as needed. Additive, not a wipe-and-replace — the standard way to move data between two instances (e.g. local → a fresh deploy). Also reachable from anywhere via the sidebar's **File** menu, alongside Settings and Log Out — kept off the topbar and out of the nav list to keep both tidy
- **Export a single project** — a project's own "⋯" menu has **⬇️ Export This Project** (downloads just that project, its sub-folder, and their tasks as JSON — the same format the full account export uses, so it can be re-imported the same way) and **☁️ Save to Google Drive**, which uploads that same snapshot to your Waypoint Backups folder (created automatically the first time, same as the account-wide Drive backup) as `<Project Title>.json` — saving again overwrites that one file in place rather than piling up dated copies, so it's always just the latest version
- **Trash** — deleting a project or task no longer removes it outright: it's soft-deleted (a `deletedAt` timestamp, filtered out of every normal list/API response) and shows up in Settings → Trash, where it can be **restored** or **deleted forever**, one at a time or all at once with **Delete All Forever** (shown only when Trash actually has something in it). Deleting a project soft-deletes its sub-folders and every task under them together, and restoring the project brings all of them back with it; a task deleted on its own restores independently. Anything sitting in Trash for 30 days is purged automatically (swept lazily whenever Trash is opened, no separate cron job)
- **Dark mode** — includes a genuine iOS-style sliding switch (not a button with a changing label) for both this and the daily email digest toggle in Settings
- **Apple-style nav & Settings** — colored icon badges throughout the sidebar (each project's own color, for its own nav link) and Settings section headers; a persistent selected-state highlight in the sidebar (a bug fix along the way — the static nav items never actually got one before, only per-project links did); Settings' Appearance/Notifications merged into one grouped "Preferences" card with a divider between rows, iOS Settings-app style, instead of two separate boxes
- **Glass UI** — an iOS-style translucent material look throughout: a soft gradient wallpaper behind everything, with cards, the sidebar, modals, and pill/toggle buttons all frosted glass (`backdrop-filter: blur` + translucency) rather than flat colors, in both light and dark mode. Applied as global overrides keyed to Tailwind's existing `bg-white`/`bg-gray-100`/`bg-gray-50` utility classes — the same technique dark mode itself uses — so it's consistent everywhere without having retrofitted a new class onto ~2000 lines of templates. Modal/onboarding content boxes get a near-opaque variant instead, since they sit on a dark dimming backdrop rather than the page's own wallpaper, and blurring that straight through would read as muddy grey rather than a clean surface
- **Mobile responsive layout**

## Tech stack

- **Backend**: Node.js (22+) + Express, `better-sqlite3` (SQLite), `express-session` backed by `better-sqlite3-session-store` (sessions survive redeploys), `bcryptjs`
- **Frontend**: Vanilla JS + Tailwind CSS (CDN) — no build step
- **Exports**: `exceljs` (Excel), `puppeteer-core` (PDF/image reports), `googleapis` (Drive/Sheets)
- **AI**: `@anthropic-ai/sdk` (Claude, tool-use for structured output — task prioritization and file-to-project extraction), `multer` (file uploads)

## Setup

```bash
npm install
cp .env.example .env
```

Edit `.env`:

| Variable | Required | Notes |
|---|---|---|
| `SESSION_SECRET` | Yes (production) | Generate with `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` |
| `PORT` | No | Defaults to `3000`; most hosts set this automatically |
| `DB_PATH` | No | Defaults to `backend/db/lifetracker.sqlite`. On most cloud hosts the filesystem resets on redeploy — point this at a mounted persistent volume in production |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` / `GOOGLE_REDIRECT_URI` | No | Powers both Google Drive backup/export AND "Sign in with Google". Create in Google Cloud Console → APIs & Services → Credentials, and add **both** `.../api/drive/callback` and `.../api/auth/google/callback` as Authorized redirect URIs on that one OAuth client |
| `NODE_ENV` | No | Set to `production` when deployed, so session cookies require HTTPS |
| `PUPPETEER_EXECUTABLE_PATH` | No | Path to a Chromium-family browser, used for PDF/image reports and the Gantt chart's image export. The `Dockerfile` sets this to the Chromium it installs — only set it yourself on a non-Docker host |
| `ANTHROPIC_API_KEY` | No | Only needed for the "✨ AI Insights" button on the Actions page. Get one at [console.anthropic.com/settings/keys](https://console.anthropic.com/settings/keys) |
| `GMAIL_USER` / `GMAIL_APP_PASSWORD` | No | Powers the daily digest email. `GMAIL_APP_PASSWORD` is **not** your normal Gmail password — generate one at [myaccount.google.com/apppasswords](https://myaccount.google.com/apppasswords) (requires 2-Step Verification on that Google account). Leave both blank to disable the feature |
| `APP_URL` | No | Public URL used for the "Open Waypoint" link in digest emails, since a background email job has no incoming request to derive it from. Defaults to `http://localhost:3000` |

Run it:

```bash
npm start        # production
npm run dev       # auto-restart on change (nodemon)
```

Then open `http://localhost:3000`.

## Deploying

A `Dockerfile` is included and is the recommended path — it installs Chromium (needed for PDF/image exports) and runs it with `--no-sandbox`, which containers require since they run as root with no sandbox namespace available. A `Procfile` (`web: node backend/server.js`) is also included for buildpack-style platforms, but without Chromium pre-installed those platforms will show PDF/image export errors unless you separately configure a Chromium buildpack and set `PUPPETEER_EXECUTABLE_PATH`.

### Railway (recommended)

1. Create a new project from this repo — Railway detects the `Dockerfile` automatically.
2. **Attach a volume**: mount it at `/data`, then set `DB_PATH=/data/lifetracker.sqlite`. Without this the SQLite database (and every session) is wiped on every redeploy.
3. Set environment variables: `SESSION_SECRET` (generate one — see the table below), `NODE_ENV=production`, `APP_URL` (your Railway domain, once you have it), and `ANTHROPIC_API_KEY`/`GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET`/`GOOGLE_REDIRECT_URI`/`GMAIL_USER`/`GMAIL_APP_PASSWORD` if you want those features live. Don't set `PUPPETEER_EXECUTABLE_PATH` — the Dockerfile already does.
4. Once Railway gives you a domain, if you're using Google features, go back to Google Cloud Console and add **both** `https://<your-domain>/api/drive/callback` and `https://<your-domain>/api/auth/google/callback` as Authorized redirect URIs on the OAuth client, and update `GOOGLE_REDIRECT_URI` to the first one.

### Any other host

1. Set `SESSION_SECRET` and `NODE_ENV=production`.
2. Attach persistent storage and set `DB_PATH` to a file inside it — otherwise the SQLite database is wiped on every redeploy.
3. Make sure a Chromium-family browser is available and set `PUPPETEER_EXECUTABLE_PATH` to it — used for PDF/image reports and the Gantt chart's image export. Building from the included `Dockerfile` handles this automatically.
4. Set the Google OAuth variables only if Drive backup / Sign in with Google should be enabled — see the redirect URI note above.

Sessions are stored in the same SQLite database (`better-sqlite3-session-store`) rather than in memory, so — as long as `DB_PATH` points at persistent storage — logins survive redeploys instead of forcing everyone to sign in again each time.

## iPhone

An APK only installs on Android — iOS can't sideload one, and there's no workaround for that. Instead, the web app itself is set up for Safari's "Add to Home Screen": with the `apple-mobile-web-app-*` meta tags and `apple-touch-icon` in `frontend/index.html`, that gives a real full-screen app icon on the home screen with no browser chrome, entirely free (no Mac, no Apple Developer account, no Xcode). A proper native iOS app (App Store or sideloaded) would additionally need a Mac with Xcode and, to distribute it at all, a $99/year Apple Developer account.

## Android app

`mobile/` is a thin [Capacitor](https://capacitorjs.com) wrapper — a real installable Android app whose WebView just points at the live Railway deployment (`mobile/capacitor.config.json` → `server.url`). There's no separate mobile codebase to maintain: any change pushed and deployed to Railway shows up in the app immediately, no rebuild needed. A rebuild is only needed for things baked into the native shell (app name/icon, the URL it points at).

Not published to the Play Store (personal use only) — it's installed by sideloading the APK directly. The app icon (`frontend/icons/`, generated from a single SVG) is shared between the web manifest and the Android launcher icon (both the flat pre-Android-8 icon and the adaptive icon's foreground/background layers).

The Android `appId` is still `com.lifetracker.app`, left over from before the app was renamed to Waypoint — intentionally not changed, since Android treats a different `appId` as a different app entirely rather than an update to the one already installed. Changing it is possible any time (edit it in `mobile/capacitor.config.json` and `mobile/android/app/src/main/res/values/strings.xml`, then rebuild), it would just mean reinstalling on any phone that already has the old one.

**Rebuilding the APK** (requires a JDK 21 and the Android SDK command-line tools — set `JAVA_HOME` and `ANDROID_HOME` first):

```bash
cd mobile
npx cap sync android        # only needed after changing capacitor.config.json
cd android
./gradlew assembleDebug     # gradlew.bat on Windows
```

The APK is written to `mobile/android/app/build/outputs/apk/debug/app-debug.apk`. To install it on a phone: enable "Install unknown apps" for whatever app you use to open the file (e.g. Files, Chrome), transfer the APK over (USB, email to yourself, cloud drive), and tap it — or with the phone connected via USB and USB debugging on, `adb install app-debug.apk`.

## Project structure

```
backend/
  server.js           entry point, middleware, route mounting
  db/                  SQLite connection, schema/migrations, data-access layer
  middleware/          session auth gate
  routes/              one file per API resource (auth, projects, tasks, drive, ai, reports, data, profile)
  reports/             Excel/PDF/image export generation, plus the Gantt chart's image export
frontend/
  index.html           all pages/modals (single-page app, no router)
  js/app.js            UI logic, rendering, event handling
  js/api.js            thin fetch wrapper for the backend API
mobile/
  capacitor.config.json  points the Android WebView at the live Railway URL
  android/               native Android project (Capacitor-generated)
```

Personal data files (e.g. `AdekolaProjects/`) are gitignored and never pushed — this repo is public.
